# 경제 모델 설계 패턴

> 게임 경제 = 자원의 *생성(source)·소비(sink)·전환* 시스템. 균형 = source ≈ sink.
> 균형 깨지면 인플레이션 또는 디플레이션 → 게임 가치 시스템 붕괴.

## 핵심 원리

게임 경제의 본질은 *간단한 등식*:

```
플레이어 보유량 = 누적 source - 누적 sink
```

이 등식이 *시간 함수*로 어떻게 진화하는가가 경제 설계의 전부.

---

## 자원 (Currency) 분류

### Hard Currency (경성 재화)
- 획득 어려움, 가치 안정
- 유료 결제 또는 마일스톤 보상
- 예: 보석, 크리스탈, 토큰

### Soft Currency (연성 재화)
- 획득 쉬움, 가치 변동
- 일상 플레이 보상
- 예: 골드, 코인, 점수

### Resource (자원형)
- 특정 활동에 소비
- 비축 어려움 (수명 또는 한도)
- 예: 에너지, 스태미나, 재료

### Premium Currency (프리미엄)
- F2P 게임의 결제 단위
- 광고·결제로 획득
- 예: 젬, 다이아

### 원칙

- **종류 적게**: 2~3 가지 권장. 5 가지 이상은 인지 부하.
- **명확한 역할**: 각 재화의 *목적*이 다름 (경성 = 진보, 연성 = 일상)
- **상호 변환**: 어느 방향으로 변환 가능한지 명시

---

## Source (자원 생성)

자원이 *어디서* 오는가.

### 전형적 source

| Source | 빈도 | 예시 |
|--------|------|------|
| 액션 보상 | 매 행동 | 적 처치 → 골드 |
| 챌린지 보상 | 가끔 | 미션 완료 → 보너스 |
| 마일스톤 보상 | 드물게 | 레벨업 → 큰 보상 |
| 일일 보상 | 매일 | 로그인 → 토큰 |
| 결제 | 사용자 결정 | 결제 → 보석 |
| 광고 | 사용자 결정 | 광고 시청 → 자원 |

### Source 설계 원칙

- **활동 비례**: 더 많이 플레이 = 더 많이 획득 (linear)
- **다양성**: 한 source 만 있으면 단조. 3~5 source 권장.
- **상한**: 무한 누적 방지 (또는 명시적 sink 보장)
- **F2P 친화**: 광고·결제 source 가 *유일*하면 P2W

---

## Sink (자원 소비)

자원이 *어디로* 가는가.

### 전형적 sink

| Sink | 영구 | 예시 |
|------|------|------|
| 영구 업그레이드 | ✅ | 스킬 트리 해금 |
| 일회성 구매 | ✅ | 아이템 구매 |
| 소모품 | ❌ | 포션, 부적 |
| 도전 입장료 | ❌ | 던전 입장 |
| 감가상각 | ❌ | 시간 경과로 자원 소멸 |

### Sink 설계 원칙

- **의미 있는 선택**: 매 sink 가 플레이어 *결정* 의 결과
- **위계 (Hierarchy)**: 작은 sink + 중간 sink + 큰 sink 다층
- **인플레이션 방지**: source 증가하면 sink 도 증가
- **만족 분비**: 큰 sink 후 즉각 *느낄 수 있는* 변화

---

## Source ↔ Sink 균형

### 측정

```
일정 기간 (예: 1 시간 플레이) 의 source 합계 = sink 합계 ?
```

미달 시:
- **디플레이션**: 자원 부족 → 진보 막힘 → 좌절
- **인플레이션**: 자원 과잉 → 가치 손실 → 의미 없음

### 균형 원칙

| 시점 | 균형 |
|------|------|
| 초반 (FTUE ~ 첫 5h) | source 약간 많음 (기쁨·진보 보장) |
| 중반 (5~20h) | 균형 (선택의 무게) |
| 후반 (20h+) | sink 약간 많음 (희소성·도전) |

### 함정

- "초반 부유 → 후반 부족" — 갑작스런 절벽
- 한 sink 가 다른 모든 sink 를 압도 (지배 sink)
- source 의 90% 가 한 활동에서 (단조)

## 변환율 (Conversion Rate)

자원을 *다른* 자원으로 바꾸는 비율.

### 예시

```
점수 → 골드: 100 점 = 1 골드
골드 → 보석: 1000 골드 = 1 보석
보석 → 영구 업그레이드: 5 보석 = 1 업그레이드
```

### 곱셈 의미

각 단계의 *상대적* 가치가 곱해짐:

```
점수 100 → 골드 1 → 보석 1/1000 → 업그레이드 1/5000
```

→ 100 점 = 업그레이드 1/5000. 즉 50만 점 ≈ 업그레이드 1개.

### 원칙

- **단방향 다수**: 보통 점수 → 골드 → 보석 (역방향 어려움)
- **변환 마찰**: 변환 시 약간 손실 (10~30%) — 비축 동기 약화
- **명시적 변환 UI**: 자동 변환 금지. 사용자가 선택.

## 인플레이션 통제

장기 플레이 시 자원 누적 → 가치 하락.

### 통제 패턴

#### 1. Hard Cap (한도)
- 최대 보유량 제한 (예: 골드 99,999)
- 초과 시 source 차단 또는 자동 변환
- 단점: 상한 도달 시 source 의미 없음

#### 2. Decay (감쇠)
- 시간 경과로 자원 감소 (예: 일일 -1%)
- 비축 어려움
- 단점: 좌절감 (얻은 게 사라짐)

#### 3. Soft Reset (소프트 리셋)
- 매 런·시즌마다 일부 자원 리셋
- 예: 로그라이트의 런 내 자원 vs 영구 업그레이드 자원
- 가장 깔끔한 통제

#### 4. Sink Inflation (싱크 가격 인상)
- 후반으로 갈수록 sink 가격 ↑
- 예: 업그레이드 비용이 지수 증가
- 자원이 누적해도 sink 도 따라 증가

#### 5. Currency Conversion (재화 변환)
- 초과 자원을 상위 재화로 변환
- 예: 골드 100 = 보석 0.1 (자동)
- 인플레이션 자원 → 디플레이션 자원

## F2P / 비-F2P 패턴

### F2P (Free-to-Play)
- 시간 제약 (스태미나, 일일 제한)
- 광고·결제 source
- Hard / Soft / Premium 3 재화 분리
- *Pay-to-Skip* (시간 단축) vs *Pay-to-Win* (능력 차이)

### Premium (1회 구매)
- 시간 제약 없음
- 결제 source 없음
- 1~2 재화로 충분
- 깊은 sink 위계

본 파이프라인은 둘 다 지원. 단, F2P 패턴 사용 시 윤리 검증 (Loss Aversion·Variable Ratio Ethics gdd-evaluation 참조).

## 시뮬레이션 (Spreadsheet 모델)

설계 후 검증:

```
시간(h) | 누적Source | 누적Sink | 보유량 | 다음 sink 까지
1       | 1000       | 800      | 200    | 가능
5       | 5000       | 4500     | 500    | 가능
10      | 10000      | 9500     | 500    | 가능
20      | 20000      | 19000    | 1000   | 가능
50      | 50000      | 50000    | 0      | 부족!
```

→ 50h 시점에 자원 0 = 디플레이션. 사용자 좌절. 조정 필요.

## 안티패턴

### 1. Source 무한, Sink 부족
"많이 줘서 좋아하겠지" → 자원 가치 0.

해결: 모든 source 에 대응되는 sink. 1:1 매칭.

### 2. 단일 source / 단일 sink
한 활동만으로 모든 자원 획득·소비.

해결: 3~5 source + 3~5 sink. 다양성.

### 3. 변환율 임의 결정
"이 정도면 적당하지" → 균형 무너짐.

해결: 변환율 = 시간 비례. "10 분 플레이 = 10 골드" 식 명확한 산정.

### 4. 인플레이션 통제 없음
50h+ 플레이어가 자원 100M 보유 → 모든 sink 의미 없음.

해결: 위 5가지 통제 중 최소 1개.

### 5. 결제 = 능력 차이
P2W. 결제 안 한 사용자가 *질 수밖에* 없음.

해결: 결제 = 시간 단축 또는 미적 가치. 능력 동등.

## 검증 체크리스트

- [ ] 재화 종류 명시 (2~3 권장)
- [ ] 각 재화의 source 3~5개 식별
- [ ] 각 재화의 sink 3~5개 식별
- [ ] 변환율 명시 (재화 간)
- [ ] 시간축 시뮬레이션 (1h, 5h, 10h, 20h, 50h)
- [ ] 인플레이션 통제 패턴 적용
- [ ] F2P 시: 결제 = 시간 단축 또는 미적 (P2W 아님)
- [ ] 균형 깨질 신호 식별 (디플레이션·인플레이션 임계점)
