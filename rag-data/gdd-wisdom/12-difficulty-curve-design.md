# 난이도 곡선 설계 패턴

> 난이도 = 도전과 능력의 상대적 균형. 정적 곡선 + 동적 조절 (DDA) 의 조합.
> 곡선이 너무 빠르면 좌절, 너무 느리면 지루함 — Flow 채널 안에 머물도록 설계.

## 핵심 원리

Csikszentmihalyi Flow 이론에 따르면 몰입은 도전(Challenge) 과 능력(Skill) 의 균형에서 발생:

```
도전 ▲
     │     ╱  좌절 영역
     │   ╱
     │ ╱       Flow 채널
     │╱      ╱
     │     ╱
     │   ╱
     │ ╱     지루 영역
     └──────────────▶ 능력
```

플레이어 능력은 시간에 따라 *증가*. 따라서 도전도 *증가*해야 함. 단, 너무 가파르거나 너무 평평하면 채널 이탈.

## 곡선 형태

### 1. 선형 (Linear)
```
도전 ▲
     │      ╱
     │    ╱
     │  ╱
     │╱
     └──────▶ 시간
```
- 일정 비율로 증가
- 예측 가능, 단조로움
- 짧은 게임에 적합 (1~3시간)

### 2. 계단형 (Stepped)
```
도전 ▲     ┌───
     │   ┌─┘
     │ ┌─┘
     │┌┘
     └──────▶ 시간
```
- 단계 (스테이지·레벨) 마다 점프
- 학습 → 정착 → 다음 단계
- 클래식 RPG·플랫포머

### 3. 지수형 (Exponential)
```
도전 ▲           │
     │          ╱
     │        ╱
     │   ╱
     │╱─
     └──────▶ 시간
```
- 후반 급격 상승
- 마스터리 측정에 적합
- 로그라이트·아케이드

### 4. S 자형 (Sigmoid)
```
도전 ▲       ───
     │     ╱
     │   ╱
     │ ╱
     │╱──
     └──────▶ 시간
```
- 초반 천천히 → 중반 가속 → 후반 안정
- 가장 자연스럽다고 평가
- 액션 RPG·메트로배니아

### 5. 톱니파 (Sawtooth)
```
도전 ▲   ╱│  ╱│  ╱│
     │  ╱ │ ╱ │ ╱ │
     │ ╱  │╱  │╱  │
     │╱   ╱   ╱   
     └──────▶ 시간
```
- 점진 상승 → 잠깐 하락 (휴식) → 다시 상승
- 긴 게임의 페이싱
- AAA 캠페인 게임

### 게임별 추천

| 장르 | 추천 곡선 |
|------|----------|
| 로그라이트 (한 런) | 지수형 (마지막에 절정) |
| 로그라이트 (전체 진보) | 계단형 (난이도 잠금 해제) |
| 메트로배니아 | S 자형 (능력 해금에 따라) |
| 액션 RPG | 톱니파 (보스 사이 휴식) |
| 아케이드 라운드 | 지수형 |
| 플랫포머 | 계단형 (스테이지) |

## 도전 차원 (Difficulty Dimensions)

도전은 한 가지가 아님. 다중 차원으로 분해:

| 차원 | 예시 |
|------|------|
| **반응 속도** (Reflex) | 적 등장 빈도, 입력 윈도우 |
| **인지 부하** (Cognitive) | 동시 활성 요소 수, 정보 양 |
| **공간 추론** (Spatial) | 길찾기, 위치 기억 |
| **자원 관리** (Resource) | 체력·재화·시간 압박 |
| **전략 깊이** (Strategic) | 빌드 선택, 메타 결정 |
| **불확실성** (Uncertainty) | 랜덤 요소, 정보 은폐 |

각 차원이 *별도* 로 증가 가능. 한 차원만 올리면 단조, 여러 차원 동시는 압도적.

### 예시 (낚시 미니게임의 차원별 진행)

```
런 시작 ─────────── 30초 ─────────── 60초
반응:    1.0초 → 0.7초 → 0.5초 → 0.4초 → 0.3초
인지:    3 → 4 → 5 → 6 → 7 (동시 오브젝트)
자원:    여유 → 여유 → 압박 (시간) → 압박 → 압박
불확실:  50% → 40% → 30% → 25% → 20% (LEGENDARY 비율)
```

## DDA (Dynamic Difficulty Adjustment)

플레이어 *실제* 능력에 맞춰 실시간 조절.

### 측정 신호

| 신호 | 의미 |
|------|------|
| 성공률 | (성공/시도) — 80% 이상 = 너무 쉬움, 50% 이하 = 너무 어려움 |
| 시도 횟수 | 같은 챌린지 반복 — 5회 이상 실패 = 어려움 |
| 진행 속도 | 시간/체크포인트 — 느리면 어려움 |
| 사용자 행동 | 회피·재시도·종료 — 부정적 행동 = 좌절 |

### 조절 강도

| 강도 | 설명 |
|------|------|
| **Subtle** | 알아채기 어려움 (적 체력 ±5%, 아이템 드랍 ±5%) |
| **Moderate** | 인지 가능하나 자연스러움 (적 종류 가감, 보너스 등장) |
| **Aggressive** | 명시적 (난이도 모드 자동 전환, 가이드 활성) |

**원칙**: Subtle 우선. 플레이어가 *조절됐음을 모르게*. Aggressive 는 명시적 옵션으로만.

### 안티-DDA 함정

DDA 가 잘못되면:
- **러버밴딩**: 플레이어가 잘하면 어려워지고, 못하면 쉬워짐 → 노력 무의미
- **의존성 학습**: DDA 가 항상 도와주면 플레이어가 능력 발전 안 함
- **불공정 인식**: "왜 이번엔 갑자기 어려워?"

해결:
- DDA 는 *실패 다음에만* 완화. 성공 시 그대로 유지.
- 누적 보정 한도 (예: ±15% 이상 안 가게)
- 명시적 난이도 옵션도 함께 제공

## 페이싱 (Pacing) 패턴

곡선의 *지역적* 변화. 짧은 시간 단위의 강도 조절.

### 패턴

| 패턴 | 설명 |
|------|------|
| **긴장-휴식** (Tension-Release) | 강한 챌린지 후 짧은 휴식 |
| **호흡** (Breathing) | 점진적 가속 + 감속 반복 |
| **클라이맥스** (Climax) | 끝으로 갈수록 강도 증가 |
| **매들** (Throughline) | 큰 흐름 안에 작은 변주 |

### 페이싱 신호

좋은 페이싱:
- 플레이어가 "한 번 더" 라고 함
- 세션 후 만족 + 적당한 피로

나쁜 페이싱:
- 30분 이상 같은 강도 → 단조
- 휴식 없이 계속 강도 → 번아웃
- 휴식이 너무 길어서 흐름 끊김

## 곡선 검증

### 정량 측정 (자동)

```
1. 플레이테스트 데이터 수집:
   - 단계별 성공률·실패율
   - 단계별 평균 시도 횟수
   - 이탈 시점 분포

2. 비교:
   - 의도된 곡선 vs 실제 곡선
   - 의도된 성공률 vs 실제 성공률

3. 차이 분석:
   - 너무 쉬운 구간 (성공률 > 90%)
   - 너무 어려운 구간 (성공률 < 30%)
   - 이탈 핫스팟
```

### 정성 측정 (플레이테스트)

질문:
- 너무 쉬워서 지루한 구간이 있었나?
- 너무 어려워서 포기하고 싶은 구간이 있었나?
- "딱 좋다" 의 구간은 어디였나?
- 어디서 가장 몰입했나?

## 안티패턴

### 1. 곡선 없음 ("일정한 난이도")
플레이어 능력 향상 무시 → 후반 지루.

### 2. 가파른 첫 30분
FTUE 와 충돌. 신규 플레이어 이탈.

해결: 첫 30분은 평탄 또는 매우 완만. 메카닉 도입에 집중.

### 3. 차원 1개만 조절
반응 속도만 올림. 다른 차원 변화 없음 → 단조.

해결: 2~3 차원 동시 변주.

### 4. DDA 완전 의존
정적 곡선 없이 DDA 만. 일관성 없음.

해결: 정적 곡선 + DDA 보정 (±10% 정도).

### 5. 곡선 매개변수 하드코딩
변수가 코드에 박혀있음 → 튜닝 어려움.

해결: 데이터 파일 (YAML/JSON) 로 분리. 디자이너가 직접 조정.
