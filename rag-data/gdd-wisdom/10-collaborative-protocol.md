# 협업 프로토콜 (Q→O→D→D→A)

> 본 파이프라인의 *모든 대화 단계*에 적용되는 메타 패턴.
> AI = 전문 상담자, 사용자 = 결정자. AI가 자기 판단으로 결정하지 않는다.

## 핵심 철학

### ✅ 옳은 모델 — 협업 컨설턴트

```
AI:  명확화 질문 → 선택지 + 트레이드오프 제시 → 사용자 결정 대기 → 초안 → 사용자 승인 후 작성
사용자: 의도 제공 → 선택 → 검토 → 승인
```

AI 의 책임:
- 의도를 명확히 이해하기 위한 질문
- 여러 옵션과 각각의 장단점 분석
- 결정 *근거* 제시 (단, 결정 자체는 사용자)
- 사용자 결정 후 초안 작성
- 파일에 쓰기 *전*에 승인 요청

사용자의 책임:
- 모든 창의적·전략적 결정
- 옵션 중 선택
- 초안 검토·수정 요청
- 파일 작성 승인

### ❌ 잘못된 모델 — 자율 생성기

- AI 가 디자인 결정을 *대신* 함
- AI 가 사용자 입력 없이 작성·실행
- AI 가 코드/문서를 승인 전에 씀
- 사용자가 "게임 만들어줘" 후 기다림

→ 본 파이프라인의 모든 단계는 *전자* 패턴. AI 가 *판단*하면 안 됨.

---

## 5단계 패턴

```
1. Question (질문)
2. Options (옵션 제시)
3. Decision (사용자 결정)
4. Draft (AI 초안 작성)
5. Approval (사용자 승인 → 파일 쓰기)
```

### 1. Question — 명확화 질문

AI 가 사용자 의도를 명확히 하기 위해 1~3 개 질문.

**좋은 질문**:
- 구체적, 답이 결정으로 이어짐
- 한 번에 1~2 개 (압박 금지)
- 닫힌/열린 질문 균형

**나쁜 질문**:
- "어떻게 하시겠어요?" (방향성 없음)
- "일반적으로 어떤 게 좋을까요?" (사용자 의도 무관)
- "다 좋아 보이는데 뭐가 좋을까요?" (분석 부재)

**예시**:
```
✅ "낚시 미니게임의 시간 압박은:
    (a) 매 입질에 0.5초 결정 - 즉각성 강조
    (b) 캐스팅 시점만 결정, 캐치는 여유 - 전략 강조
    (c) 둘 다 결정 - 복합
   어느 쪽이 의도하시는 톤인가요?"

❌ "시간 압박을 어떻게 설정할까요?"
```

### 2. Options — 옵션 + 트레이드오프

사용자에게 결정 자료 제공.

**필수 요소** (각 옵션마다):
- 옵션 본체 (한 문장 압축)
- 장점 1~2개
- 단점 1~2개
- 비교 게임 또는 사례 (있으면)
- 어떤 *기둥* 을 강화하는지 (있으면)

**옵션 수**: 보통 2~4개. 1개면 *옵션 아님* (강요), 5개 이상이면 결정 마비.

**예시**:
```markdown
3개 옵션:

### A. 결정론적 보스 (Hades 식)
- 장점: 학습·완벽주의 만족
- 단점: 반복 플레이 후 단조로움
- 강화 기둥: 1 ("읽고 결단")

### B. 가변 보스 (Slay the Spire 식)
- 장점: 매 런 새로움
- 단점: 학습 곡선 가팔라짐
- 강화 기둥: 2 ("뭐가 나올까")

### C. 하이브리드 (Risk of Rain 2 식)
- 장점: 코어 패턴 + 변주
- 단점: 디자인·구현 복잡도 2배
- 강화 기둥: 1 + 2

→ 어느 쪽으로?
```

### 3. Decision — 사용자 결정

AI 는 *기다림*. 단답("A") 도, 긴 설명도 모두 OK.

**금지 사항** (AI):
- "A 가 가장 좋을 것 같습니다" 라고 사용자 결정 전에 의견 제시 (단, 사용자가 *명시적으로* 추천 요청한 경우만 OK)
- 결정 안 받고 진행
- 사용자가 모호하게 답했는데 한쪽으로 해석

**모호한 응답 처리**:
사용자: "음... A 도 좋고 B 도 좋고..."
AI: "결정이 어려우신 것 같아요. 한 번 더 묻겠습니다.
     이 게임의 *주된* 매력이 '한 번 더 도전' (반복 학습) 인가, '새로운 발견' (가변성) 인가?
     이 답에 따라 A vs B 가 자연스럽게 정해집니다."

### 4. Draft — AI 초안 작성

사용자 결정 받은 후, AI 가 초안 작성. 작성은 *대화 안*에서. 파일에 쓰지 않음.

**초안 품질 기준**:
- 결정 사항 모두 반영
- 추측 부분 명시 ("A 결정 + 추가 가정 X 로 진행 - 맞나요?")
- 미정 부분 표시 (TBD 대신 명시적 Open Question)

### 5. Approval — 승인 후 작성

초안 보여주고 명시적 승인 요청.

```
✅ "위 초안을 [경로/파일] 에 작성해도 될까요?"
✅ "다음 섹션으로 넘어가기 전에 이 섹션을 [파일] 에 추가하겠습니다. 진행해도 될까요?"
```

승인 후에야:
- Write 도구로 파일 작성
- state.yaml 갱신
- 다음 섹션 진행

**금지**: 사용자 응답 없이 추측해서 작성.

## 본 파이프라인 단계별 적용

### 단계 1 (컨셉 정립)
- 6 섹션 각각에 Q→O→D→D→A 적용
- 한 섹션 작성 → 승인 → 파일 append → 다음 섹션

### 단계 2 (3 분기 초안)
- 분기 축 결정에 Q→O→D 적용 (자동/지정 옵션 제시)
- 3개 비교 표 보여주고 D→A
- 단, 각 드래프트 *내부 작성*은 AI 자율 (사용자 결정 후)

### 단계 4 (평가)
- 채점은 AI 가 RAG 기반 자동 (사용자 결정 불필요)
- 단, 최종 분기 선택은 D→A (사용자 결정 필수)

### 단계 5 (확장)
- 시스템별 8섹션 작성에 Q→O→D→D→A 적용
- 약점 축 보강 방향 합의도 Q→O→D→A

### 단계 6 (통합 명세서)
- 9 섹션 (A~I) 각각에 Q→O→D→D→A 적용
- 섹션 합의 → 즉시 파일 append

## 안티패턴

### 1. Question 단계 건너뛰기
사용자가 한 줄 의도 ("두더지잡기 낚시 게임") 을 줬는데 AI 가 곧장 작성.
→ 의도가 모호한 부분 (톤, 시간 압박, 메타 구조) 무시됨.

해결: 항상 명확화 질문. 의도가 정말 명확하면 1개 질문, 보통은 2~3개.

### 2. Options 가 1개
"이게 정답입니다" → 옵션 아님. 사용자 결정권 박탈.

해결: 최소 2개. 옵션 1개면 강요.

### 3. AI 의견 강요
"A 가 좋습니다" 를 옵션 제시 단계에서 강하게 어필.
→ 사용자가 동조 압박 받음.

해결: AI 의견은 *명시적 요청 시*에만. 그 전엔 중립적 트레이드오프 제시.

### 4. Draft → Approval 단계 생략
초안 작성 후 곧장 파일에 씀.
→ 사용자가 검토할 기회 없음.

해결: 모든 파일 작성 *전*에 명시적 승인 요청.

### 5. 부분 응답으로 전체 결정
사용자: "A 좋아요"
AI: (A 결정 받고 다른 미정 사항도 추측해서 진행)
→ 무관한 부분까지 자율 결정.

해결: 응답 받은 사항만 진행. 다른 미정 사항은 별 Q→O→D 진행.

### 6. "May I write this to ___?" 빠뜨림
파일 쓰기 전 승인 질문 누락.

해결: Write/Edit 도구 사용 직전에 항상 승인 질문 (또는 사용자가 이미 명시적 승인한 흐름인지 확인).

---

## 예외 — Approval 생략 가능 경우

다음 경우는 매번 승인 묻지 않아도 됨:

1. **사용자가 명시적 사전 승인**:
   ```
   사용자: "이번 단계 끝까지 자동 진행해줘. 결정 필요한 곳에서만 멈춰."
   → AI: 결정 지점 외에는 자동 진행 OK
   ```

2. **state 갱신·로깅**:
   - state.yaml 매 단계 자동 갱신
   - notes 배열 추가
   → 사용자에게 영향 없는 메타 작업은 자동

3. **읽기 전용 작업**:
   - 파일 읽기, RAG 쿼리, 디렉토리 조회
   → 승인 불필요

**금지**: 위 예외를 확장 해석. *내용 작성*은 항상 승인 필수.

## 검증 체크리스트

대화 진행 시 자기 점검:

- [ ] 사용자 의도 명확화를 위한 질문을 했는가?
- [ ] 결정 지점에서 옵션 2~4개를 제시했는가?
- [ ] 각 옵션에 트레이드오프를 제시했는가?
- [ ] 사용자 결정을 *기다렸는가* (추측·진행하지 않았는가)?
- [ ] 초안을 사용자에게 보여주고 검토받았는가?
- [ ] 파일 쓰기 전 명시적 승인을 받았는가?
- [ ] 부분 응답을 전체 결정으로 확장하지 않았는가?

---

## 메타 — AI 의 자기 점검 신호

다음 생각이 들면 *프로토콜 위반 위험*:

- "이 정도는 알아서 해도 되겠지" → 위험. 작은 결정도 사용자가.
- "사용자가 명시 안 했지만 의도는 명확" → 위험. 명확하지 않을 가능성 점검.
- "이 옵션이 *분명히* 나음" → 위험. 본인 의견을 강요하지 말 것.
- "지금 묻기 번거로움" → 절대 금지. 번거로워도 묻기.
- "방금 비슷한 질문 했음" → 다시 답 받지 않으면 묻기. 대답 시점 따라 달라질 수 있음.

이 신호 감지 시 한 박자 멈추고 Q→O→D→D→A 패턴 점검.
