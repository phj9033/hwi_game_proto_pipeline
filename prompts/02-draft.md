# 단계 2 — 3개 메카닉·장르 분기 초안 생성 (AI 생성 + RAG)

## 목적
1단계 컨셉을 동일하게 유지하되, **메카닉/장르를 다르게** 변주한 3개의 얇은 GDD 초안을 생성한다.
이후 단계 4에서 이 3개를 5-Axis 로 평가하여 최선의 방향을 선택한다.

## 산출물
- `workspace/<slug>/02-draft-A.md`
- `workspace/<slug>/02-draft-B.md`
- `workspace/<slug>/02-draft-C.md`

## 사전 작업

1. `01-concept.md` 전체 읽기
2. 컨셉에서 keywords 추출 (장르 후보, 핵심 동사, 톤, 타겟 등)
3. RAG 쿼리 (있는 컬렉션만):
   ```bash
   hwicortex query "<keywords> mechanic alternatives genre branch" -c genre-mechanic-lexicon --json -n 5
   hwicortex query "<keywords>" -c gdd-references --json -n 3
   ```
   미등록 컬렉션은 스킵하고 LLM 자체 지식 사용.

## 분기 축 결정

사용자에게 한 번 묻는다:
- "3개 분기 축을 자동 선정할까요, 아니면 직접 지정할까요?"
- 자동: 컨셉 분석 → LLM 이 명확히 다른 메카닉/장르 3개 제안 → 사용자 확정
- 지정: 사용자가 직접 3개 메카닉/장르 입력

**자동 선정 시 가이드라인**:
- 동일 컨셉의 핵심 판타지를 유지하되, 핵심 동사·정보 형태·결정의 모양을 다르게
- 3개가 서로 의미 있는 차이가 있어야 함 (변주 축이 다양해야 평가가 의미 있음)
- 예시 (낚시 컨셉이라면):
  - A: 두더지잡기식 클릭 액션
  - B: 카드 덱빌딩 (낚시대·미끼를 카드로)
  - C: 리듬 액션 (입질 박자에 맞춘 타이밍)

## 각 드래프트 작성 가이드

각 드래프트는 ~800~1500 단어. 다음 섹션을 포함:

```markdown
# [프로젝트 슬러그] — 분기 [A|B|C]: <분기 이름>

## 분기 축
- **핵심 메카닉**: <변경된 메카닉 1줄>
- **장르 분류**: <Steam 태그 2~3개>
- **원 컨셉 대비 변경점**: 핵심 판타지는 유지, [무엇]이 다름

## 한 줄 요약
"..."

## 코어 루프 (3~6단계)
[행동 A] → [정보] → [결정] → [행동 B] → [보상] → 반복

## 핵심 시스템 3~5개

### 시스템 1: <이름>
- **책임**: ...
- **핵심 룰 1~3개**: ...
- **플레이어 결정**: ...

### 시스템 2: ...
(반복)

## 플레이 시간 모델
- 한 세션: <분>
- 한 런/스테이지: <분>
- 의도된 반복 횟수: <회>

## 검증 가설 (프로토타입에서 검증할 것)
- H-1: <메카닉 가설> — "[조건]일 때 플레이어는 [반응]한다"
- H-2: <난이도 가설>
- H-3: <보상/동기 가설>

## 차별성 (vs 다른 두 분기)
- A 대비: ...
- B 대비: ...
(혹은 유사작 대비)

## 알려진 리스크
- 메카닉 리스크: ...
- 스코프 리스크: ...
```

## 작성 절차

1. 분기 축 3개 확정 후, 사용자에게 1줄 요약 보여주기:
   ```
   A: ...
   B: ...
   C: ...
   계속 진행? (y/n)
   ```
2. 사용자 OK 시 3개 드래프트 순차 작성 (각각 한 번에)
3. 각 드래프트 작성 후 한 줄 요약만 보고 ("A 작성 완료: <분기명>")
4. 3개 모두 완료되면 비교 표 출력:

   | 분기 | 핵심 메카닉 | 장르 | 차별 포인트 | 가장 큰 리스크 |
   |------|------------|------|------------|---------------|
   | A | ... | ... | ... | ... |
   | B | ... | ... | ... | ... |
   | C | ... | ... | ... | ... |

5. 단계 완료 → "다음: `/cp-next` 로 4단계 평가 진행"
