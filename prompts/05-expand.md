# 단계 5 — 선택 드래프트 상세 확장 (대화 + RAG)

## 목적
4단계에서 선택된 드래프트를 깊이 있는 GDD로 확장한다.
4단계 평가의 약점 축을 우선 보강하고, 시스템을 5~10개로 세부화하며, 공식·엣지케이스를 명문화한다.

## 산출물
`workspace/<slug>/05-detailed-gdd.md`

## 사전 작업

1. `01-concept.md` 읽기
2. `02-draft-{selected}.md` 읽기 (state.yaml.artifacts.selected_branch 기준)
3. `04-eval-report.md` 읽기 — 특히 선택 드래프트의 약점 축 식별
4. 📚 RAG 사용 단계 — 현재 미연결, 본 단계는 LLM 자체 지식으로 진행 (rag_queries 인터페이스는 pipeline.yaml 에 보존)

## 확장 전략

선택 드래프트의 약점 축을 식별하고 우선순위 결정:

| 약점 축 | 보강 방법 |
|---------|-----------|
| A 구조 | 모호한 메카닉 명문화, 의존성 명시, Living Document 형식 적용 |
| B 동기 | SDT 욕구 매핑(자율·유능·관계), Octalysis 8 Core Drives 점검 |
| C 인지 | FTUE 흐름 설계, 정보 계층화, Cognitive Load 분산 |
| D 정합 | MDA 역추적 (의도 감정 → 메카닉), 시스템 간 상호작용 매트릭스 |
| E 실현 | 스코프 재단(MoSCoW), 프로토타입 가설 명확화, 의존성 위험 제거 |

가장 점수 낮은 축 1~2개를 집중 보강. 다른 축은 유지 또는 가벼운 정리.

## 작성 절차

### Step 5.1 — 확장 계획 합의

사용자에게 다음 보고:
```
선택 분기: [X]
4단계 점수: A:_ B:_ C:_ D:_ E:_  (종합 _.__/5.0)
약점 축: [축 1, 축 2]

확장 우선순위 제안:
1. <약점 축 1 보강> — <구체 방법>
2. <약점 축 2 보강> — <구체 방법>
3. 시스템 N개 → M개로 세부화
4. 핵심 공식 명문화
5. 엣지 케이스 정리

이대로 진행? (y / 수정 요청)
```

### Step 5.2 — 섹션별 incremental 작성

다음 섹션을 1개씩 합의하며 파일에 추가:

```markdown
# <project-slug> 상세 GDD — 분기 [X] 확장본

## 1. 컨셉·기둥 (1단계 + 분기 조정 반영)
- 한 줄 요약
- 게임 기둥 3개
- 핵심 판타지 (3~5줄)
- USP

## 2. 코어 루프 (확장)
- 단계별 다이어그램
- 각 단계의 플레이어 결정
- 정점 모먼트 식별

## 3. 시스템 인벤토리 (5~10개)
각 시스템마다:
- **이름**
- **책임 (한 줄)**
- **핵심 룰 2~5개**
- **공식** (있으면)
- **의존 시스템**
- **튜닝 노브 1~3개**

## 4. 핵심 공식
| 공식 | 변수 | 범위 | 예시 계산 |
|------|------|------|----------|
| ... | ... | ... | ... |

## 5. 엣지 케이스
- 케이스 1: <상황> → <명시적 처리>
- 케이스 2: ...
- (최소 5개)

## 6. 약점 축 보강 노트
4단계에서 식별된 [축 1, 축 2] 보강 내용:
- 축 1: <구체적 변경>
- 축 2: <구체적 변경>

## 7. 검증 가설 (정련)
2단계의 H-1~H-3 에 추가/정련:
- H-1: ... (정량화)
- H-2: ...
- (총 3~7개)

## 8. 인수 기준 (Acceptance Criteria)
- AC-1: <테스트 가능한 조건>
- AC-2: ...
- (최소 5개)

## 9. 알려진 위험·미결정 사항
- 위험 1: ...
- 미결정: ...
```

### Step 5.3 — 자기 점검

작성 완료 후 LLM 자기 점검:
1. 선택 드래프트의 약점 축이 보강되었는가?
2. 시스템 인벤토리에 핵심 시스템이 모두 있는가?
3. 공식과 엣지 케이스가 모호하지 않은가?
4. 인수 기준이 테스트 가능한가?

자기 점검 결과를 사용자에게 1줄로 보고:
```
자기 점검: ✅ 4/4 통과  (또는 ⚠️ 다음 항목 미흡: ...)
```
